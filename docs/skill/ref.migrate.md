# ref.migrate: 更新后的目录迁移与重新适配
上级: ref
下级: 无
---
游戏更新可能产生新的 `bin/<构建>/res_mods`，旧目录安装不会因此自动成为当前安装。
```
wowsmod migrate --dry-run
wowsmod migrate --from <旧构建或旧res_mods目录>
wowsmod migrate --keep-old
```
先确认当前游戏根目录、构建、旧安装登记与项目来源；命令选项以 `migrate --help` 为准。dry-run 查看计划，实际迁移写游戏目录，需要相应授权。

**迁移做什么**：把已登记的旧安装迁到目标目录，并按新客户端重新补齐原版占位资源。`game_files_updated_since_install` 是资源变化线索，不是兼容性或视觉结论。需要原项目/包的解包目录；来源失效时恢复来源或用保留的包重新制定安装计划，别编造旧项目。

**重新适配(rebase)是什么**：当前资源结构/挂点/材质发生变化时，以当前构建的 SDK 与 extractSources 重新建基底，再有依据地重放自己的编辑。这里描述制作过程，没有承诺 `rebase` 命令。先保留旧项目，核对来源的船与构建；不能只修改 `mod.toml` 构建号冒充适配。

制作构建不同/未知 → “需当前版本验证”，不是直接“不兼容”。失败时列具体缺资源/结构/来源原因。项目中的占位合法，安装后未补齐则是问题；完成后分别保留文件、注册日志与获授权港口视觉证据。迁移成功不自动完成这些验收。
