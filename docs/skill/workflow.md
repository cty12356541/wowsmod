# workflow: 从需求与参考到可验证的外观
上级: root
下级:
- workflow.replicate: 有参考视频/图片，要复现其设计
- workflow.theme: 从角色与作品提炼主题语言
- workflow.original: 从风格、情绪与用途定义方向
- workflow.book: 记录设计依据、选定方向与验收范围
- workflow.layers: 只执行本次需要的制作层
- workflow.review: 对照意图和证据复盘
- workflow.changelog: 查历史案例或沉淀可复用改进
---
**主流程**：理解需求/参考 → 最小小样 → 选定方向 → 相关层制作 → 工作台检查 → 获授权后的港口验收。单次换色、局部修正直接走对应 `ref` 节点，记录目标、修改与证据即可，不强制设计书、三方向或模型流程。
**整套制作**：有参考读 replicate；角色主题读 theme；原创读 original。先写 `workflow.book`，用小样解决真正的分歧；已有明确设计或用户选择就继续执行。选择设计方向不等于授权安装或启动游戏。
**设计判断**：按参考/意图分别检查轮廓、图案、材质、发光；新增模型取决于参考与目标。颜色可从参考量取，比例、明暗、尺寸与强度由该项目定义；不把案例色号、面积或统一评分当通用门槛。保留远近可读、动作不受阻、避免意外穿模的检查。
**能力与证据**：区分已验证(注明构建/船/场景)、实验和未知。预览近似不代表游戏实证；缺能力就列出差距与可选做法，不把图案替换为不相符的程序线，也不把动画/自定义发光宣布为可靠。
**素材**：记录来源与许可；原版素材和受限第三方资源按许可使用，分发前读 `ref.pack`。复盘先写项目，重复的通用问题再考虑更新全局指引。
