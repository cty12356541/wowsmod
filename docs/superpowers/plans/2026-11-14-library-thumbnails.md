# 制作库默认视角封面与交付

用户授权：为制作库加入默认视角截图，整理完整需求完成表及后续优化建议，提交并推送远端。沿用当前工作台的浅色视觉和 `deck` 斜俯视机位，不启动 WebGPU 迁移或新一轮 Mod 美术改造。

## 实施约定

- 每个方案使用自己的真实渲染图。船卡使用筛选后的可用代表方案，方案卡按稳定项目 ID 取图。
- 图片为 640 × 360 PNG，默认 `deck` 机位、当前修订、日间材质、固定 LOD。无头渲染需修正 `deck` 映射，保留独立 CLI 的历史默认机位。
- 可见卡片按需请求状态。图片在应用数据目录缓存，制作库列表不等待模型加载；旧图可在刷新期间继续展示。失败提供占位与重试。
- 后台串行出图，复用当前服务的项目会话及 scoped CDP，避免为同一项目重复装配或关闭用户会话。源目录、客户端、输入修改和渲染版本参与失效判断；发布前检查输入稳定与项目身份。
- 路由：`GET /api/v1/library/projects/{id}/thumbnail` 返回 `ok,state,url,stale,reason,width,height`，状态为 `queued/rendering/ready/failed/missing`；`GET .../thumbnail/{sha256}.png` 读取缓存；`POST .../thumbnail/refresh` 显式刷新。路径段按 URI 编码，磁盘路径使用散列身份。

## 分工与验证顺序

1. 后端：队列、缓存、路由、正确组合 scoped render URL，验证隔离、去重、输入变化和失败恢复。
2. 前端：共享封面、惰性请求、有限轮询、旧图与错误回退，覆盖真实 `deck` 映射及状态转换。
3. 文档：逐项对应历史请求，区分完成、有限验证、待规划与仅讨论；提出有代码依据的改进候选。
4. 集成：重建嵌入前端，运行相关前后端测试及独立审查，实际生成知更鸟封面，检查桌面与窄屏布局、缓存命中和预览入口。
5. 交付：更新原本机服务并保留库数据，在右侧浏览器展示；完成表记录实际证据。用户追加要求远端主分支以本地版本为准。远端主分支与本地历史不同，合并保留两边历史，以已验收本地代码为最终树，再正常推送 `main` 和 `codex/mod-library`，直接核对远端 SHA。

验收记录放在 `out/library-thumbnail-20261114/`，稳定需求清单为 [requirements-status.md](../../requirements-status.md)。后续建议仅列为候选，不自动扩大本轮实现范围。
