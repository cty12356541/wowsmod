# 多 Mod 制作库、同船方案切换与制作指引

日期：2026-11-13。状态：待用户确认；本文尚不代表功能已经实现。

## 目标与已确认需求

用户希望先提升工具链，再深度优化知更鸟 Mod。本轮明确选择：多 Mod 制作时提供类似游戏船库的筛选；同一条船允许保存多个 Mod 方案，在工作台选择、预览，并显式应用到游戏；精选打磨工具内指导 AI 制作 Mod 的 skill。

成功标准是：用户能够找到某条船的多个方案，清楚知道正在编辑哪个、游戏实际应用哪个，可靠地切换应用；AI 能沿简明且有依据的指引制作不同风格，而不会把 Robin 个案参数套到所有项目。

## 方案与取舍

采用“制作库 → 单船方案列表 → 现有工作台”。现有工作台已有部件、贴图、时间线和模拟区域，把整个项目库挤入常驻侧栏会占用 3D 视口。独立制作库更适合多维筛选，并允许保留当前工作台。

考虑过工作台左栏新增项目标签：少量项目切换很快，但多船、多筛选的浏览空间不足，而且无刷新切换需要清理全部请求、SSE 和 3D 缓存。首版打开不同项目使用明确的项目 URL 和完整页面载入，减少状态串项目；无刷新切换留作后续优化。

用户已确认工作台选择、预览与应用到游戏的范围；制作库布局和本文实现边界是本次建议，待确认。不做游戏内 Mod 切换菜单。

## 第一版范围

### 1. 制作库

- 管理已有 `mod.toml` 项目；提供添加项目、扫描指定制作目录、重新定位失效目录、从库移除。移除仅取消登记，不删除项目文件。
- 首版展示已有项目对应的船，不展示整个游戏中没有项目的舰船。现有 `mod init/import-sdk` 保持可用，添加项目后进入制作库；本轮不另造新船 SDK 下载/导出向导。
- 按国家、等级、舰种、制作状态筛选，支持收藏、名称搜索与最近打开/最近修改排序。多选同一维度为“或”，不同维度为“且”；搜索匹配船名、船代码、方案显示名和标签。筛选为空时不过滤。
- 船按稳定参数代号分组；船卡显示名称、国家/等级/舰种、方案数和当前应用概况。SDK 名与 GameParams 参数名通过明确映射归一，不从目录名字猜国家。
- 未识别船保留显示为“未识别”，无目标船的 loose 项目列为“全局/未关联”；两者不伪造船属性。
- 点击船显示其方案列表。方案卡包含显示名称、版本、制作状态、最后修改、目录简称、制作客户端构建和独立的安装标记。
- 制作状态是用户维护的“制作中 / 待验收 / 已完成 / 已归档”；它不是自动的游戏兼容或实机验收结论。安装标记另行呈现“未应用 / 当前应用 / 应用内容已落后 / 文件异常 / 状态未知”。
- 已归档项目默认隐藏，可通过筛选显示。返回制作库保留筛选、选船和滚动位置。无项目、无筛选结果、目录失效分别给出明确入口。

示意结构（沿用当前浅色/深色工作台的视觉语言，不复制游戏装饰）：

```text
制作库                  搜索船名 / 方案 / 标签         添加项目  扫描目录
国家 ▾   等级 ▾   舰种 ▾   制作状态 ▾   收藏 ☆        最近打开 ▾

勃艮第 · 法国 X 战列舰 · 3 个方案
  知更鸟 · 制作中      当前应用        [预览 / 继续制作]
  深海蓝 · 待验收      未应用          [预览 / 继续制作]
  原创方案 · 已归档                    [预览 / 继续制作]

工作台面包屑：制作库 / 勃艮第 / 知更鸟     [切换方案] [应用到游戏]
```

### 2. 项目身份、存储和船属性

- 新增独立本地项目库，默认保存于 `WOWSMOD_HOME/library.json`，沿用工具已有 home 解析规则。库格式带版本号，原子写入，损坏时保留原文件并明确报错。
- 每个登记记录有稳定 `project_id`、规范化路径、显示名称、标签、收藏、制作状态和最近打开时间。现有 `mod.toml` 保持兼容；不把 `mod.name` 当身份，也不因浏览而改写项目。
- Windows 大小写、目录联接和相对路径规范化后去重。不同路径中的同名项目分别存在；重新定位保留 ID。复制一个项目并添加时形成新的库记录，不继承其安装身份。
- 扫描只遍历用户指定的根目录，发现项目后不进入其资产/缓存/安装备份；不扫描全盘，不跟随会形成循环的链接。失效或无权限路径作为可见问题返回，不丢弃其他合法项目。
- 船属性复用 `ShipParam` 与本地化名称，按客户端根目录和构建号缓存。无游戏或解析失败时仍可浏览项目，缓存属性标明来源，无法确定的属性留空。
- 库列表只读取轻量元数据，不为每张卡生成 GLB、解码贴图或启动浏览器。

### 3. 项目预览隔离

- 保留 `wowsmod preview <项目>`、现有无头 `render` 和 MCP 调用。
- 增加制作库启动入口与项目登记/列举 CLI；具体命令树在实施计划中锁定。图形界面和 CLI 共享同一目录库。
- 库打开项目时才创建预览会话；所有库项目请求、资源、任务和事件流携带明确项目 ID，不能依赖一个全局“当前项目”。
- 首版切方案完整重载工作台；多标签页不得互相改变编辑或安装目标。已有单项目兼容入口仍限定到启动项目。
- 贴图/步骤缓存按项目和修订隔离；关闭或切换时释放 viewer、计时器和事件连接。
- 预览读取实际项目装配。不得为无法解析的船静默加载勃艮第种子或模拟参数；缺素材显示具体原因，缺模拟数据则禁用该能力，不冒充支持。

### 4. 应用到游戏与同船切换

- 浏览、筛选和选择方案只影响工作台。只有明确的“应用到游戏”操作才能写客户端目录。
- 按当前游戏根目录、构建号和规范船 ID 判断已应用方案，不凭项目 `.install` 是否存在或名称相同判断。
- 同船 SDK 方案一次应用一个。提交应用前显示当前方案 → 新方案、目标客户端版本及必要警告；用户点击该动作即确认此具体替换。
- 不使用 `--allow-same-ship` 叠装。其他船/全局 Mod 的资源仍进行逐文件冲突检查，未经选择不卸载其他方案。
- 安装计划先在内存/暂存区补齐新方案资源、检查冲突，再在单一安装锁和可恢复事务内替换。出现写入失败须还原旧文件、备份、共享归属和登记表，不能调用现有“卸载后再安装”的非原子组合。
- 回滚依据是切换前的实际安装快照，不依赖旧项目路径仍存在，也不依赖旧游戏资源仍可解包。发现旧安装被用户修改时停止并说明，不覆盖其改动。
- 游戏运行时拒绝安装/切换/卸载。失败、断电/进程中止后保留事务记录，并在下一次修改前完成恢复或明确阻止继续写入。
- 旧项目构建不同显示“需当前版本验证”，不直接断言不兼容；文件完整、注册日志、实机视觉结果是不同证据。点击应用不自动启动游戏，不把成功写入标为实机验收通过。
- 一并修正现有 HTTP `/uninstall` 被 `ends_with("install")` 误判、子进程未传当前 `--game`、同名项目安装标记混淆的问题。不可用的撤回/恢复按钮按能力明确禁用，不能假装动作可执行。

### 5. 内置制作 skill 的精选

保留已有渐进式帮助树和构建时嵌入机制。本轮优先精修高频路径，而非扩充所有节点。

- 入口先确认项目、目标船、当前客户端及已应用方案，再路由到“单操作”或“整套制作”。新增一个按需的多方案管理节点，引用本轮真实实现的命令。
- 统一主流程为：理解参考/需求 → 小样与方向选择 → 分层制作 → 工作台检查 → 获授权后的港口验收。按任务跳过不相关层；换色不强制完整造型流程，大型主题制作需要设计依据。
- 保留高价值方法：不只看封面；分开轮廓、图案、材质、发光；同机位对比；关闭发光仍检查涂装可读性；是否新增模型由参考决定；不用等宽程序线代替需要笔触的图案。
- 固定色号、光强、配色比例、羽翼厚度及 P5/C2 挂点等属于案例，不作为所有船/风格必须通过的阈值。已有案例资料保留并注明船、构建、港口、验证范围和未解决问题。
- 明确区分已验证能力、实验能力和未知事项。自定义部件发光、动画挂载不写成普遍可靠；新增 26.11 动画能力需有当前 dump 与实机证据，不能仅改文字宣布支持。
- SDK 来源按船和客户端构建记录；“迁移目录/补齐占位”与“重新适配模型”分别说明。合法项目中的占位资源和安装后遗留占位必须区分。
- 制作复盘写入该项目；重复且通用的问题才成为工具/skill 改进候选，不要求每做一层就改全局指引。
- 纠正 PowerShell 颜色参数引号、打包保留必需 `Main.py` 等命令契约问题。保持旧 help 节点 ID 可访问；移动案例后保留跳转，不让现有链接失效。
- 验证结构/链接、命令示例和关键场景：简单换色、有视频的复刻、角色主题、未知版本、多方案切换。修改 Markdown 后重建二进制验证嵌入内容；说明既有 `ai init` 产物需要显式刷新。

## 工程边界与建议落点

Rust：新增项目库、船目录共享层与安全应用服务；复用格式解析、项目加载、安装 registry 和预览状态，避免重写资源格式。

前端：新增制作库页面和独立库状态，扩展顶栏、API 类型和状态标记；尽量保留大纲、贴图、历史与 3D 编辑器。

当前本机前端源码位于仓库外 `preview_app/web`，而 Rust 仓库跟踪嵌入产物；后台脚本还会刷新外部源码。实施将在隔离开发目录内保存可版本管理的前端源码，与后端一起构建，使用确定的构建/同步命令生成嵌入产物并记录来源。不会让自动同步脚本覆盖本次工作，不改远端历史，也不合并全部不相关公共分支改动。

安装事务、库逻辑、前端和 skill 文档分别承担明确职责。Rust 2021 + 当前 React/TypeScript/Three.js 技术栈保持；新增依赖只在有必要时引入。

## 不包含

- 游戏内实时换 Mod、运行中的热安装、同时叠加同船多个 SDK 外观。
- 本轮直接重做知更鸟美术，或承诺解决其自定义部件夜间发光。
- 自动下载第三方 Mod/SDK、云同步、公开发布、全盘搜集项目。
- 所有舰船完整运动模拟、新的全功能建模编辑器或重写解包格式。
- 重写所有 66 个帮助节点、以个案实验替代通用制作方法。

## 验收

1. 至少两个不同船项目、同船三个方案及一个全局项目可登记、筛选、切换工作台；同名副本不合并，失效目录可重新定位。
2. 国家/等级/舰种/状态组合、中文/英文搜索、收藏、空结果、归档与返回库状态有可重复验证；至少桌面宽屏和窄窗口无不可达操作。
3. 两个标签页查看不同项目，贴图、时间线、安装任务和资源不串用；现有单项目预览和无头出图回归通过。
4. 假客户端中，同船 A→B 成功只启用 B；补齐/冲突检查失败时 A 未变；写入中失败或进程中止后可恢复 A，文件及登记哈希一致；其他船和共享资源保持。
5. 游戏运行、外部改动、旧项目路径失效、多个安装根目录、同名项目及更新构建均有针对性测试；卸载 HTTP 真正卸载并使用指定客户端。
6. 当前 Robin 项目作为兼容样本，浏览和预览不得改其原始文件；技能树和命令契约验证通过。真实游戏测试另按已授权范围安排，不由自动化测试直接启动。

## 尚留给实施者的选择

库字段的精确 Rust/TypeScript 类型、CLI 子命令拼写、路由内部组织、缩略图缓存和样式细节由实施计划确定。不得改变上述项目身份、显式应用、同船互斥、回滚、实际能力展示和只扫描指定目录的行为边界。
